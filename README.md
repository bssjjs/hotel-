# hotel-insight：酒店预订的客源、节奏与取消

用 `data/hotel.db` 里的 119,390 条预订记录（2015-07 至 2017-08，两家酒店）回答四个问题：
**客人从哪来、什么时候来、房型由什么决定、取消和什么有关**——以及落到行动上的最后一步：
**哪些是结构性的，哪些真的能干预**。

所有数字由脚本从库里算出：16 项质量检查（DQ-01—DQ-16）、四步清洗、
五个分析模块（`origin` / `timing` / `room` / `cancel` / `rate`）、八种图型。
notebook、报告、图表取自同一份中间结果，改一个口径三处一起变。

## 结论

| 问题 | 一句话 | 数字 |
| --- | --- | --- |
| 从哪来 | 长尾很长，但钱和人都在少数国家 | 176 个客源国，前 10 占 82%，葡萄牙一国 30% |
| 什么时候来 | 提前期是取消最强的单一信号，严格单调 | ≤7 天 8.4% → >90 天 37.0%，中间没有回落 |
| 房型 | 房型是门店属性，不是客人偏好 | 各国 A 房型占比都在 50%–84%，差异跟着门店走 |
| 取消 | 影响面最大的几项都改不了 | 渠道 3,952 单、提前期 3,711 单、客源国 3,036 单超额取消 |
| 结构 vs 干预 | 涨的 6.4 个百分点里，结构效应可以忽略 | 客源结构 −1.1pp（客人变好），渠道结构 +1.3pp，其余在组内 |

三条硬结论，交付物里都要带着：

1. **没有"影响大且可改"的杠杆。** 12 个因素按"超额取消单 vs 可干预性"铺开，右上角是空的。
   能改的（特殊要求、停车位）影响中等，而且已经被业务动作污染，不能直接当因果。
2. **客源变差解释不了取消率上涨。** 同月对比取消率 25.9% → 32.2%（+6.36pp），
   按客源国分解的结构效应是 **−1.14pp**；按渠道分解组内效应占 79%。
   是同一批渠道、同一批客人在更晚地取消，不是换了一批客人。
3. **`deposit_type` 是陷阱，不是杠杆。** "不可退款"组取消率 94.7%，是"无押金"的 4 倍，
   与直觉相反——它是取消**之后**的结果，不是原因，禁止当预测特征（标签泄漏）。

## 怎么开始

1. 把 `hotel.db` 放进 `data/`（单文件 SQLite 库）。
2. 在项目根目录安装：`python -m pip install -e .`（可编辑安装）。
3. 命令行跑一遍流水线：

```bash
python -m hotel_insight.pipeline --db data/hotel.db
```

4. 打开 `notebooks/D01-口径与底座.ipynb`，内核选 **`signal`**（conda 环境 `signal` 自带，Python 3.12 + pandas 3.0），
   从第一格往下跑。D01 钉死口径，后面五本不再重复解释。

## 五条口径（报告里必须照抄）

- **取消率有三种口径**：含重复 37%、去重 27%、清洗后 **27.85%**。分析一律用清洗后 85,585 行。
- **"取消"不纯**：未到店 1,207 行被计入 `is_canceled=1`；需要区分时用 `reservation_status`。
- **均价排除 0 值**：`adr` 有 1,959 行为 0，算均价一律 `adr > 0`（SQL 侧 `NULLIF(adr, 0)`）。
- **同比只用 1—8 月**：26 个月里只有 2016 是完整年，跨年比较固定取两年都有的 1—8 月（`comparable_months`）。
- **小样本不单独下结论**：分组不足 30 单（`min_group_n`）、交叉格子不足 20 单（`min_cell_n`）不上图、不算率。

## 边界

只有两家酒店，所有结论限定在这两家（DQ-14）；库里**没有酒店所在地区/城市字段**，
"地区"只能用客源国代替；无房量分母，所以只能讲均价与结构，讲不了入住率与客房收入。

团队工程规范见 `AGENTS.md`；分析设计与指标定义见 `docs/分析提纲.md`，需求与清洗规则见 `docs/需求规格.md`。
