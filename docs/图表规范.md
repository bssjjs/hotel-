# 图表规范

适用范围：本项目的全部图表——notebook 出图、Word 报告插图、汇报 PPT、展示平台。
代码实现：`src/hotel_insight/viz/`（`theme.py` 管语义色与收尾，`styles/*.mplstyle` 管外观）。
答辩或交付前，按第 8 节清单逐项检查。

## 0 字体：只用开源字体

**这是合规红线，不是审美偏好。** 微软雅黑、苹方、宋体、黑体、Times New Roman 都是商业字体，
系统里装着是随操作系统授权，但把指定了这些字体的图片、报告、PPT 分发出去，授权范围不一定覆盖。

| 角色 | 本项目选用 | 替代的是 | 许可证 |
| --- | --- | --- | --- |
| 图表中文（标题、标注） | **Noto Sans CJK SC**（思源黑体） | 微软雅黑 / 苹方 / 黑体 | SIL OFL 1.1，可免费商用 |
| Word 报告正文 | **Noto Serif CJK SC**（思源宋体） | 宋体 / SimSun | SIL OFL 1.1 |
| 西文衬线（报告正文） | **TeX Gyre Termes** | Times New Roman | GUST Font License |
| 西文兜底（负号、上下标） | **DejaVu Sans** | — | Bitstream Vera，matplotlib 自带 |

实现在 `styles/base.mplstyle` 的一行：

```mplstyle
font.family: Noto Sans CJK SC, Noto Serif CJK SC, TeX Gyre Termes, DejaVu Sans
```

**为什么写多个名字**：matplotlib 3.6+ 的 `font.family` 会逐字回退——中文找思源黑体，
缺的字形（负号、上下标）由 DejaVu Sans 补。只写 `font.sans-serif` 时只用第一个找到的字体，
中文负号会变方框（`axes.unicode_minus` 因此保持 True）。

**为什么图表用黑体、报告正文用宋体**：屏幕上黑体更清晰、更像"数据产品"；长文阅读宋体更省力。
这是对上游项目（signal-insight）实现的一处有意修正——那份项目的规范写"图表用黑体"，
代码里却用了 `Noto Serif CJK SC`，两边不一致；本项目按规范执行。

本机实测（2026-10-18）：`Noto Sans CJK SC`、`Noto Serif CJK SC`、`TeX Gyre Termes`、`DejaVu Sans` 均已安装；
`Source Han Sans SC` / `Source Han Serif SC`（Adobe 命名）未装，但同字形，不影响。

## 1 一张图由五部分组成

| 部分 | 要求 |
| --- | --- |
| 标题 | 写结论、带数字、≤40 字；数字必须由代码算（f-string），不能手敲 |
| 副标题 | 写口径：对象、时间、分母、限制；1–2 行 |
| 图形 | 只画回答标题所需的内容 |
| 标注 | 直接写在图上，少用图例；条末写数值 |
| 来源行 | 左下角浅灰小字：数据来源 + 脚本名 |

统一由 `viz.finish(fig, 标题, 副标题, 来源, 文件名)` 完成：它加主色短条、标题、副标题、来源行，
并按英寸留出上下空白（`margins_in`），最后存到 `image/`（300 dpi）。

标题长度有断言：`assert len(title) <= 40`。画完还要做**读回断言**——从图对象把数读回来核对，
例如 `[b.get_width() for b in ax.containers[0]]` 必须等于中间表。靠代码，不靠眼睛。

## 2 颜色：蓝色打底

原则：**蓝色打底，一种颜色强调一件事，红色只表示警示，灰色只作衬托。**

| 用途 | 色值 | 代码 |
| --- | --- | --- |
| 主色（强调对象） | `#1D6FA5` | `MAIN` |
| 主色浅 / 中 / 深 | `#DCEAF5` / `#7FB3D9` / `#174E73` | `MAIN_LIGHT` / `MAIN_MID` / `MAIN_DARK` |
| 衬托、背景对象 | `#C4CAD3` / `#8E99A6` | `GRAY` / `GRAY_DARK` |
| 警示、不通过 | `#D64545` | `RED` |
| 警告 | `#B7791F` | `AMBER` |
| 标题正文 / 副标题 / 来源行 | `#1F2937` / `#6B7280` / `#9CA3AF` | `INK` / `MUTED` / `FAINT` |

**固定映射**（所有图、报告、平台一致）：

- 酒店：城市酒店 `#1D6FA5`，度假酒店 `#7FB3D9` → `viz.HOTEL_COLOR[名称]`
- 状态：通过 `#7FB3D9`、警告 `#B7791F`、不通过 `#D64545` → `viz.STATUS_COLOR[状态]`
  （"通过"用浅蓝而不是绿：本项目整体偏蓝，一张图里出现三种色相会散）
- 分类色按蓝色由深到浅：`#174E73 → #1D6FA5 → #4A93C4 → #7FB3D9 → #A9CDE6 → #DCEAF5` → `viz.BLUES`

连续数值用单色蓝渐变（`image.cmap: Blues`），不用彩虹色阶。

## 3 字号

| 元素 | 字号（磅） |
| --- | --- |
| 标题 | 16，加粗 |
| 副标题 | 10.5 |
| 坐标轴标签、刻度 | 10–10.5 |
| 图内标注 | 9–10.5 |
| 来源行 | 8.5 |

刻度字号不得小于 8 磅。画布默认 `figsize=(10, 5.6)`（16:9），Word 插图按 A4 版心另配。

## 4 选图：问题决定图形

| 要回答的问题 | 用 | 不用 |
| --- | --- | --- |
| 随时间怎么变 | 折线、上下双面板 | 双 Y 轴 |
| 几类之间比大小 | 横向条形，按大小排序 | 饼图（>5 类） |
| 量与率同时出现 | 上下两个面板，共用横轴 | 同一张图两条纵轴 |
| 构成（占比） | 堆叠条 + 段内写"状态 项数" | 3D 饼图、环形图 |
| 流程的逐级减少 | 横向条形（长度就是行数） | 漏斗图的斜边 |
| 两个指标的关系 | 散点图 | 双轴折线 |
| 重复/分布 | 直方图、ECDF | 只给平均数 |

### 4.1 八种图型（`viz/charts.py`）

图型不自由发明——同一个问题永远用同一种形状，读者第二次看就认得。新增形状前先问"能不能用这八种拼出来"。

| 函数 | 形状 | 回答什么问题 | 本次用在 |
| --- | --- | --- | --- |
| `hbar` | 横向条形，按大小排序 | 几类之间比大小，类别名较长 | 因素影响面、清洗步骤 |
| `grouped_hbar` | 横向分组条（两三条一组） | 同一批类别的两个口径对比，**含负数** | 六维度结构/组内效应 |
| `share_bar` | 单行堆叠条 | 构成占比，段内写字 | 客源 × 酒店类型 |
| `heat` | 矩阵热力 | 两个维度交叉，看模式不看精确值 | 年月覆盖、客源 × 房型、换房流向 |
| `pareto` | 条形 + 累计折线（双轴但同为"占比"语义） | 集中度：前几项占了多少 | 客源国帕累托 |
| `waterfall` | 瀑布（起点 + 增减 + 终点） | 从 A 到 B 的变化由哪几块构成 | 取消率分解 |
| `dumbbell` | 哑铃（两点一线） | 同一批类别在两个时点的位移 | 同月同比、OTA 提前期 |
| `quadrant` | 象限散点 | 两个判据同时决定优先级 | 影响面 × 可干预性 |

`pareto` 与 `heat` 是本项目对上游项目的一处扩展：上游只有前五种，而"集中度"和"交叉结构"
在这份数据里反复出现，每次都手搓会写出五套不同的样式。

### 4.2 排版上踩过的坑（都在函数里修掉了，改函数时别改回去）

| 现象 | 原因 | 修法 |
| --- | --- | --- |
| 条末数值被裁掉 | `xlim` 只到最大值 | 函数里留 28% 右侧余量；超长标签同理留左侧 |
| 浅蓝段上的白字糊成一片 | 字色写死为白 | `_ink_on(color)` 按亮度选黑/白字 |
| 哑铃图的图例压住数据 | 图例默认位置 | 图例 `upper right` + 右侧留白 |
| 象限图最底部的标签压住 x 轴刻度 | 所有点统一向下偏移 | 按档位分别给方向：最低档只朝上、最高档只朝下 |
| 分组条里 `+0` 显示成 `+0.0` | 格式化函数没处理 0 | 绝对值 < 1e-9 时显示 "0" |
| 双百分比轴互相误读 | 左轴柱高、右轴累计线各一套刻度 | 左轴刻度隐去（柱上已有数字），右轴标注"累计占比" |

## 5 禁止项

1. **双 Y 轴**：两条线的交点与高低全由刻度决定，容易误导。改上下两个面板。
2. **3D 图**：透视让大小失真。
3. **超过 5 块的饼图**：人眼比较角度很差。
4. **截断的纵轴柱状图**：柱长就是数值，必须从 0 开始（折线图可不从 0，但要说明）。
5. **图例超过 7 项**：改线尾直标，或拆成小多图。
6. **只靠颜色区分状态**：段内要写文字，色弱读者也能读。
7. **展示单笔记录的可识别信息**：对外只出现聚合结果。

## 6 数字

- 整数千分位：`2,037`，不写 `2037`。
- 百分比：≥10% 取整；1%–10% 一位小数；<1% 保留两位有效数字（不写 `0.0%`）。
  统一走 `quality.fmt_pct`，别在每个 cell 里各写一版（上游项目就吃过这个亏）。
- 单位写全："人""分钟""条""组"；时长超 2 小时改用小时。
- 差值写"个百分点"，不写"%"：`相差 10 个百分点`。
- 删失的数写"至少"；口径差异写在副标题里。

## 7 文件与命名

- `image/D{天}_{序号}_{中文主题}.png`，例如 `D02_03_重复记录对取消率的影响.png`。
- 保存 200–300 dpi；`image/` 不进 Git（随时可重生成）。
- 主题：`viz.apply_theme("default")`。交付脚本**在代码里写明主题名**，不依赖环境变量，
  否则别人换个环境变量就出另一套颜色。
- 一份交付物只用一个主题。

## 8 审图清单

| # | 检查项 | 谁检查 |
| --- | --- | --- |
| 1 | 标题是结论、带数字、≤40 字，且数字由代码算 | 断言 + 人审 |
| 2 | 副标题写了对象、时间、分母、限制 | 人审 |
| 3 | 有来源行 | `viz.finish` 保证 |
| 4 | 没有双轴、3D、>5 块饼图、>7 项图例 | 人审 |
| 5 | 柱状图纵轴从 0 开始；比例轴标了 % | 人审 |
| 6 | 颜色符合固定映射；红只用于警示 | 人审 |
| 7 | 图上的数与中间表一致（读回断言） | 断言 |
| 8 | 中文与负号显示正常，刻度 ≥8 磅 | 自检格 |
| 9 | 口径差异（含重复/去重、未到店）写进了副标题 | 人审 |
| 10 | 条末数值、图例、最外侧标签都没被裁或被遮 | 人审 |
| 11 | 结论类图形（瀑布/哑铃/象限）的假设与方向写在副标题，读者不看正文也能读懂 | 人审 |

自动断言只能挡住低级问题；"结论对不对、口径写清没有"要靠人审。
